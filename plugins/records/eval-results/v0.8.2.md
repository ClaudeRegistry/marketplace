# Records Agent Tools Eval Results v0.8.2

## Scope

- Replace the `fhir-validation-reviewer` denial list (`disallowedTools`) with an explicit least-privilege allow-list (`tools: ["Read", "Grep", "Glob", "Bash", "Skill"]`).
- Keep `Skill` in the allow-list so the agent can still load its declared `fhir-validation` skill; a four-tool list would leave the `skills:` declaration inert.
- Document the in-session `/plugin marketplace add` and `/plugin install` commands next to the existing shell form in the repository and plugin READMEs.
- No skill, script, command, fixture, or result-contract behavior changes in this release.

## Automated Checks

- `npm test`
- `npm run test:codex`
- `npm run validate:claude`
- `npm run release:check`
- `npm run check`

## Notes

- The agent tool scope is a narrowing: the previous denial list blocked only `Write`, `Edit`, and `MultiEdit` and inherited everything else, including network tools. The allow-list drops those.
- `Bash` remains in the allow-list because the reviewer runs local validators. Bash can still write files via redirection, so the allow-list bounds the agent's tool surface, not its filesystem reach. The read-only contract stays a prompt-level instruction, as it was before.
- `claude plugin validate --strict` checks manifests, not runtime tool scope, so the skill-loading path is verified by invoking the agent rather than by CI.

## Release Decision

Ship v0.8.2 only when all automated checks pass, the `fhir-validation-reviewer` agent still loads the `fhir-validation` skill under the allow-list in a live Claude Code session, and GitHub Plugin CI is green.
